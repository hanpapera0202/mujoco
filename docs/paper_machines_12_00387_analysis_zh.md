# 論文方法深度分析與本專案整合

## 來源與結論先行

來源是 Yuantian Qin、Kai Zhang、Kuiquan Meng、Zhehang Yin，**Research on
Collaboration Motion Planning Method for a Dual-Arm Robot Based on Closed-Chain
Kinematics**, *Machines*, 2024, 12(6), 387，DOI:
`10.3390/machines12060387`。論文以兩台六自由度工業手臂共同操作一個工作物，
核心不是單純換一個 IK，而是把「基座座標校正、共同工作物位姿、軌跡離散、
速度規劃」放進同一條幾何鏈。

本專案已新增，並將論文定位為高階中央派工之下的 **low-level 雙臂運動協同層**：

1. `src/closed_chain_kinematics.py`：`DualArmLowLevelLayer` 與可重用的 SE(3)
   校正、閉鏈推導、姿態誤差、同步位姿採樣、五次時間尺度與平滑成本。
2. `BayesianJointGame` 的聯合候選平滑成本：讓中央規劃器偏好較少急加速的方案，
   但不會覆蓋硬碰撞限制。
3. 單元測試與本文件，明確區分「雙臂共持一件物品」和「雙臂平行分揀不同物品」。

低階資料流固定為：

`中央任務目標 → 基座/工具 frame 校正 → 工作物閉鏈或獨立物件模式 →
位姿離散與速度時間化 → QP-RRIK → MuJoCo 碰撞/接觸驗證`。

它不會取代 BC-GP-JSP，也不會把其中一臂變成 master；兩臂仍由同一中央控制器
同時送出目標。

## 論文流程拆解

### A. 建立相對基座座標

論文讓 master 與 slave 末端依序到達三個不共線點，分別以兩個基座做正運動學，
再用三點構成同一個 calibration frame。兩個基座到 calibration frame 的矩陣
相乘後得到基座間轉換。這一步解決的不是手臂能否各自到達，而是兩個 IK 解在
同一個世界幾何中是否真的代表同一個點。

本專案用 `estimate_rigid_transform(source, target)` 做相同事情的數值穩健版本：
三點可用，四點以上則使用 SVD 的最小平方剛體配準。演算法會拒絕共線點，並在
反射解出現時修正 rotation determinant，避免校正結果翻鏡像。

### B. 把工作物當作中介座標系

論文用 world、base、workpiece rotation center、transfer flange、trajectory
point 等座標系串接：

$$T_W^{P_j}=T_W^{WP}T_{WP}^{CP}T_{CP}^{P_j}.$$ 

兩個末端不是各自追同一個數字位置，而是由同一個工作物位姿導出：

$$T_W^{E_A}=T_W^{WP}T_{WP}^{CP}T_{CP}^{FP}T_{FP}^{E_A},$$

$$T_W^{E_B}=T_W^{WP}T_{WP}^{CP}T_{CP}^{P_j}T_{P_j}^{TG}T_{TG}^{E_B}.$$

程式中對應為 `ClosedChainKinematics.peer_tool_pose`。輸入 A 的世界末端姿態與
兩個工具到物件的固定 offset，即可得到 B 應該維持的世界末端姿態；
`residual()` 再回報平移公尺誤差與旋轉弧度誤差。

### C. 連續軌跡變成同步離散指令

論文先由工作物特徵曲線產生位置和姿態，再離散成控制器能接受的點，並且讓末端
切線、工具軸方向和工件幾何一致。它展示了中心旋轉和剛體平移兩種場景，兩個
手臂的關節曲線均需位於關節限制內。

目前產線不是焊接或共同加工，因此沒有把 saddle/arc 曲線直接塞進投料流程。
保留它的工程原則：任何未來的共同持物/交接任務，都先在物件座標產生軌跡，
再轉成兩臂末端目標，最後各自進入中央的碰撞預檢和 QP-RRIK。

### D. 速度曲線與平滑性

論文在圓弧轉折使用 trapezoidal velocity planning，目的是降低衝擊並避免關節
速度突變。本專案已有分段軌跡與 smoothstep；本版再提供 quintic scaling，並把
離散聯合路徑的速度/加速度粗糙度加入 Bayesian 聯合效用：

$$U'=U-0.10C_{smooth}.$$ 

這個權重故意很小。完成率、碰撞、雙臂同動與路徑時間仍是主要因素，避免為了
「看起來平滑」而選到抓不到物或延誤出料的方案。

## 為什麼對本專案有用

### 1. 解決座標漂移與兩臂不一致

目前最大的研究風險不是公式寫不出來，而是 XML 基座、夾爪 site、真實手臂安裝
角度和 GUI 參數可能不在同一個 frame。三點校正能把這個差異量化；之後可在
MuJoCo 用已知點做回歸，在實機用教導點取得校正矩陣，再比較同一套數學的殘差。

### 2. 保留真正的中央平權協作

論文用 master/slave 方便推導，但本專案需求是兩臂同一個中央處理器、平行取得
決策。本版只把 master/slave 當作座標代數中的暫時參考，不把它變成執行權限。
中央規劃器仍可交換 A/B，兩臂各自得到路徑後同時做碰撞預檢。

### 3. 讓未來的交接不再靠猜位置

現在的輸送帶分揀是不同物件，所以閉鏈不是必要條件；但使用者規劃的「一隻手
抓取後另一隻接手」會短暫進入共同物件幾何。此時 `peer_tool_pose` 和 `residual`
可以定義交接窗口、驗證兩個夾爪相對物件的姿態，再交給現有 safety envelope，
而不是用固定 offset 或等待走廊淨空。

### 4. 改善速度與演示穩定度

只靠逐點 IK 容易在多個近似解間跳支路，造成你先前看到的蠕動。平滑成本不能
單獨解決錯誤 IK，但能在候選路徑已通過硬限制後，穩定偏好較連續的關節序列，
並提供可記錄的比較量：`smoothness_cost`。

## 不能直接照搬的部分

1. 論文工作物是兩臂共同持有的剛體；輸送帶上的兩個方塊不是同一剛體，不能在
   一般分揀模式強加閉鏈，否則會犧牲吞吐量且製造不必要的碰撞。
2. 論文的 MATLAB/Simscape 驗證主要觀察軌跡、關節曲線與實驗重現，沒有涵蓋本
   專案的動態皮帶預測、指墊接觸、掉件統計和 10 cm 警戒盒；這些仍由 MuJoCo
   的接觸與中央執行器負責。
3. 三點校正需要非共線且量測可靠的點。若三點太接近或幾乎共線，數值上會放大
   誤差；實機應使用至少四到六點並保存校正 RMS 誤差。

## 後續研究順序

1. 在 MuJoCo 先建立三個可重現 calibration sites，驗證估計的 base transform
   與 XML 已知變換一致。
2. 將 `peer_tool_pose` 接到「交接模式」的雙臂任務，不影響一般獨立抓取。
3. 對每個候選保存平移殘差、旋轉殘差、速度峰值、加速度峰值，再加入 dashboard
   的可視化；不要只看最後是否 placed。
4. 最後才把交接殘差轉成 QP 等式/軟約束，並以硬碰撞預檢和關節限位做外層保護。
