# 雙臂物理驗證報告 v0.24.0

## 範圍

在 2026-08-16 以相同的 20 個 seed 測試五組設定，共 100 次獨立 MuJoCo headless 實體回放。每次回放 35 秒模擬時間，使用雙指實體接觸判定抓取，不使用 weld/equality constraint。

實際牆鐘時間為 34.797 分鐘，100 次皆正常結束，沒有 Python 例外。

|---|---:|---:|---:|---:|---:|---:|

## 已確認事實

1. 100 次中沒有任何一筆雙臂聯合策略通過目前的 3 x 3 路徑預檢，因此 Bayesian utility 尚未真正有可行的雙臂方案可以選擇。
2. 將追蹤頻率從 12.5 Hz 提高至 25 Hz 沒有改善放置率，反而增加路徑拒絕與中止次數。
3. 將 QP 迭代數加倍可讓平均抓取數略升，但放置率仍只有每回放 0.5 件，同時平均耗時增加約 43%。
4. 將警戒領域由 10 cm 縮至 5 cm 沒有產生聯合可行解，且 IK 路徑拒絕最多；問題不是單純安全領域太大。
5. 單臂隔離的抓取數與放置數高於雙臂基準，並且 IK 拒絕、復原與路徑中止都顯著較少。低階抓取/搬運仍不穩定，但雙臂協調確實額外造成退化。

## 卡死修正

舊流程在 `conveyor_right_guard` 接觸手指後，會回復至最近安全姿勢，但下一控制週期仍命令同一個危險目標，形成無限 rollback。v0.24.0 的處理為：

- 無可行動態 IK 分支時，暫停目前任務的階段時間軸，不可偷跑到下降或閉爪。
- 已成功回復的禁止接觸，會記錄為 `path_abort`、撤銷原路徑並解除相依的 handoff，而不會忽略碰撞或持續撞回導軌。
- 導軌碰撞體仍保留；此改動只移除無限重複命令。

## 下一輪優先順序

1. **建構真正的聯合可行路徑集。** 以時空走廊/預留區段產生兩臂共同的上方接近、下降與撤離軌跡；不要先各自完成整條單臂 IK 軌跡再做 3 x 3 淘汰。
2. **讓中央排程接受不可達證據。** 某臂的動態 IK 分支全拒時，中央端要立即把該物件轉給另一臂或等待安全窗口，而不是停留在舊任務。
3. **分離抓取與搬運控制。** 抓取成功後需維持相對於夾爪的物件速度與夾持裕度；目前 `grip_lost_before_release` 是第二主要失敗型態。
4. **將預警盒改為連續距離成本。** 10 cm 領域保留作硬近失界線，但聯合最佳化應使用 signed distance barrier/QP inequality，而非只能全拒或全收。
5. **建立指標門檻。** 下一版至少要測量 joint-plan selection rate、雙臂實際移動時間重疊、抓後保持率、每件耗時與 10 件完成率；先達成可行雙臂方案再談全域效用最優。
